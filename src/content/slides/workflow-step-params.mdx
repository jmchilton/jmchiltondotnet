{/* SLIDE 2 — the problem */}

<section class="vstack">

<div class="eyebrow">The problem</div>

<h2>Changing one threshold means the whole legacy form</h2>

<div class="cards cards-3 measure-lg">
  <div class="card">
    <div class="card-eyebrow">Everything, every time</div>
    <div class="card-body">To change a threshold, a filter value or one repeat option, users open the expanded form. It renders every step and submits every unconnected parameter.</div>
  </div>
  <div class="card">
    <div class="card-eyebrow">What did I change?</div>
    <div class="card-body">The invocation keeps all of them. You can't tell the two you meant to change from the rest.</div>
  </div>
  <div class="card card-gold">
    <div class="card-eyebrow">Reruns stuck there</div>
    <div class="card-body">Four fixes make step parameters round-trip, but a rerun of such a run is forced back into the legacy form. I've held them back.</div>
  </div>
</div>

<div class="callout measure">The API can already set any of these parameters. What's missing is a light way to set <em>a few</em>.</div>

<aside class="notes">[Sources] RERUN_ISSUE.md "Problem" and "Recording exposed parameters" (galaxy-brain vault/projects/workflow_applications/); RERUN_UX.md "Problem" (the full form records every unconnected param, so rerunHasStepParameters pins reruns to the expanded form). Fixes: galaxyproject/galaxy #24178 (subworkflow export keys), #24175, #24176 (import re-keys), #24177 (rerun prefills; forces the expanded form when an invocation has step parameters). The issue's "hundreds of unchanged defaults" is illustrative; no parameter count or render timing was measured, so the slide doesn't give one. No user reports are linked in the sources: "users" here is the issue's "some users".</aside>

</section>

{/* SLIDE 3 — the proposal */}

<section class="vstack">

<div class="eyebrow">The proposal</div>

<h2>Pick a few parameters. Send only those.</h2>

<div class="flow">
  <div class="flow-node">Picker<br /><span style="font-weight: 400; font-size: 0.8em;">steps → parameters</span></div>
  <span class="flow-arrow">→</span>
  <div class="flow-node">Cards<br /><span style="font-weight: 400; font-size: 0.8em;">in the simple form</span></div>
  <span class="flow-arrow">→</span>
  <div class="flow-node">Invocation<br /><span style="font-weight: 400; font-size: 0.8em;">records exposed keys</span></div>
  <span class="flow-arrow">→</span>
  <div class="flow-node">Rerun<br /><span style="font-weight: 400; font-size: 0.8em;">re-shows them</span></div>
</div>

<div class="body measure">Each parameter has one key, <code>&lt;order_index&gt;|&lt;prefixed_name&gt;</code>, the same one the invocation request export already uses. Links, rerun and submission share it.</div>

<div class="note">Everything not picked uses the workflow's saved values.</div>

<div class="callout callout-navy callout-sm measure">To decide: file this as an issue? Pick parameters from a tree, or from the graph?</div>

<aside class="notes">[Sources] RERUN_ISSUE.md "Proposal", "Exposure key", "Recording exposed parameters", "Rerun". Subworkflow keys add one index per level: &lt;outer&gt;|&lt;inner&gt;|name. order_index is 0-based, like inputs_by: "step_index". The two questions are the branch record's "Decision" (index.md) and the two spikes.</aside>

</section>

{/* SLIDE 11 — recommendation and next steps */}

<section class="vstack">

<div class="eyebrow">Recommendation</div>

<h2>Ship the tree, with select/deselect</h2>

<div class="body measure">
<ul class="tight">
  <li><strong>Cost:</strong> strict keys (G1), parameter paths (G2), recorded keys (G4). About 20–30 server lines each, no migration. Graph later as an optional view.</li>
  <li><strong>Risk:</strong> strict keys turn silently ignored keys into 400s. The audit covered only the run/rerun test tools.</li>
  <li><strong>Gap:</strong> column parameters stay locked in the first pass, and they're probably what users most want to change.</li>
</ul>
</div>

<div class="callout measure">Ask: file the issue, then PRs in order: G1, G2&nbsp;+&nbsp;G4 API, client.</div>

<aside class="notes">[Sources] RERUN_ISSUE.md "Recommendation", "API work needed" (G1 audit scope: still check dynamic options, hidden params, __job_resource, old saved states with keys from upgraded tools) and "Picking parameters" (column follow-up); LESSONS_LEARNED.md UI lesson 3 and "Suggested issue edits" 5 ("most likely user complaint"); branch record vault/repositories/galaxy/branches/active/workflow_run_exposed_step_params/index.md "Decision". Line estimates are from the spike, not a review. Full subworkflow listing (G3) is also still to design. Neither spike will be opened as a PR.</aside>
