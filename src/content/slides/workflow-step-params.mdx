{/* SLIDE 2 — the problem */}

<section class="vstack">

<div class="eyebrow">The problem</div>

<h2>Changing one threshold means the whole legacy form</h2>

<div class="cards cards-2 measure-lg">
  <div class="card">
    <div class="card-eyebrow">What users do today</div>
    <div class="card-body">Open the expanded run form to change a threshold, a filter value or one repeat option. It renders every step and every unconnected parameter, and submits all of them.</div>
  </div>
  <div class="card card-gold">
    <div class="card-eyebrow">What's stuck</div>
    <div class="card-body">Four fixes make step parameters round-trip through the invocation API, but they target the legacy form. I've held them back.</div>
  </div>
</div>

<div class="callout measure">The API can already set any of these parameters. What's missing is a light way to set <em>a few</em>.</div>

<aside class="notes">[Sources] RERUN_ISSUE.md "Problem" in galaxy-brain vault/projects/workflow_applications/. Fixes: galaxyproject/galaxy #24178 (subworkflow export keys), #24175, #24176 (import re-keys), #24177 (rerun prefills; forces the expanded form when an invocation has step parameters). "Slow to render" is qualitative; no timing was measured.</aside>

</section>

{/* SLIDE 3 — the proposal */}

<section class="vstack">

<div class="eyebrow">The proposal</div>

<h2>Pick a few parameters. Send only those.</h2>

<div class="flow">
  <div class="flow-node">Picker<br /><span style="font-weight: 400; font-size: 0.8em;">steps → parameters</span></div>
  <span class="flow-arrow">→</span>
  <div class="flow-node">Cards<br /><span style="font-weight: 400; font-size: 0.8em;">in the simple form</span></div>
  <span class="flow-arrow">→</span>
  <div class="flow-node">Invocation<br /><span style="font-weight: 400; font-size: 0.8em;">records exposed keys</span></div>
  <span class="flow-arrow">→</span>
  <div class="flow-node">Rerun<br /><span style="font-weight: 400; font-size: 0.8em;">re-shows them</span></div>
</div>

<div class="body measure">Each parameter has one key, <code>&lt;order_index&gt;|&lt;prefixed_name&gt;</code>, the same one the invocation request export already uses. Links, rerun and submission share it.</div>

<div class="note">Everything not picked uses the workflow's saved values.</div>

<aside class="notes">[Sources] RERUN_ISSUE.md "Proposal", "Exposure key", "Recording exposed parameters", "Rerun". Subworkflow keys add one index per level: &lt;outer&gt;|&lt;inner&gt;|name. order_index is 0-based, like inputs_by: "step_index".</aside>

</section>

{/* SLIDE 11 — recommendation and next steps */}

<section class="vstack">

<div class="eyebrow">Recommendation</div>

<h2>Ship the tree, with select/deselect</h2>

<ul class="tight measure body">
  <li>Graph later as an optional "show in graph" view, not the only picker.</li>
  <li>Server work is small: strict unknown keys (G1), parameter paths for "rerun with this changed" (G2), recorded exposed keys (G4). About 20–30 lines each, no migration.</li>
  <li>Still to design: full subworkflow listing (G3) and column parameters once their data input is set.</li>
</ul>

<div class="callout measure">Next: file the issue, then split into PRs: G1, G2 + G4 API, client.</div>

<aside class="notes">[Sources] RERUN_ISSUE.md "Recommendation" and "API work needed"; branch record vault/repositories/galaxy/branches/active/workflow_run_exposed_step_params/index.md "Decision". Line estimates are from the spike, not a review. Neither spike will be opened as a PR.</aside>

export const PAYLOAD = `POST /api/workflows/{workflow_id}/invocations
{
  "inputs_by": "step_index",
  "parameters_normalized": true,
  "parameters": {
    "2": {"queries_0|column": "c3"},
    "3": {"1|cond|threshold": 0.05}
  },
  "exposed_step_parameters":
    ["2|queries_0|column", "3|1|cond|threshold"]
}`;

<div class="cards cards-2 measure-lg cards-tight">
  <div class="card"><div class="card-title">G1 · strict keys</div><div class="card-body card-body-sm">Unknown or inactive-case keys are silently ignored today. Return 400, including in subworkflows.</div></div>
