export const REFUSAL = `HTTP 403 · TOOL_EXECUTION_PRECONDITION_UNMET
err_code: 403009
unmet:
  - kind: license_agreement
    details:
      agreements: [ ...terms and declared hashes... ]`;

{/* SLIDE 8 — explain direct and asynchronous refusal semantics */}

<section class="vstack vstack-tight">

<div class="eyebrow">API and refusal handling</div>

<h2>A refused run carries a reason</h2>

<pre class="code-block code-block-lg"><code>{REFUSAL}</code></pre>

<div class="body measure"><code>POST /api/tools</code> and workflow invocations refuse immediately.<br />Forms refresh the agreements when a submission is refused.</div>

<div class="callout callout-sm measure"><code>POST /api/jobs</code> is asynchronous:<br />the tool request can be accepted, then fail in Celery with the same structured reason.</div>

<aside class="notes">[Sources] lib/galaxy/tools/preconditions.py; lib/galaxy/schema/schema.py (UnmetPrecondition discriminated on kind); client/src/api/licenseAgreements.ts; lib/galaxy_test/selenium/test_tool_license_async_failure.py; doc/source/dev/tool_license_agreements.md, Enforcement table and Refusals, at cd37d851bb2. Displayed payload is schematic YAML, not a literal HTTP response. Direct refusal is HTTP 403 with err_code 403009. Async tool request GET /api/tool_requests/id reports state failed and a state_message containing err_msg, err_code and unmet. Tool access and undeclared hashes are checked before async enqueueing; agreement authorization occurs in the worker. Access refusals have kind access; anonymous users receive a login remedy. An undeclared hash produces 400, not 403009. This distinction matters to API clients and prevents claiming every endpoint fails synchronously.</aside>

</section>
