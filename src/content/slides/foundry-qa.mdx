<div class="cards cards-3 measure-lg" style="margin-top: 18px;">

  </div>

{/* SLIDE 7 — a miss has to be earned */}

<section class="vstack">

<div class="eyebrow">01 · No wrapper</div>

<h2 class="plain-heading measure" style="font-size: 1.3em; line-height: 1.16;">A <em>miss</em> has to be earned before it counts</h2>

<div class="body measure">
  The Tool Shed's lexical index does not reliably match an underscored tool-id token. <code>integron_finder</code> returns
  nothing; <code>integron finder</code> and <code>integron</code> both score.
</div>

<div class="callout measure">
  So the skill derives query variants first — strip the owner prefix, split on <code>_</code> and <code>-</code>, try the bare
  significant word. A no-hit on the raw token alone is a <strong>search artifact</strong>, not evidence the tool is absent.
</div>

<div class="note">
  This is exactly the kind of caveat that rots in a hand-written skill and survives in a note that many Molds cite.
</div>

</section>

{/* SLIDE 8 — missing CLI tool */}

<section class="vstack vstack-tight">

<div class="eyebrow">02 · No CLI</div>

<h2>Every cast declares its own tools</h2>

<pre style="font-size: 0.44em; line-height: 1.55; text-align: left; margin-left: auto; margin-right: auto; max-width: 36em; padding: 0.9em 1.1em; border: 0;"><code style="display: block; padding: 0;">{`{

}`}</code></pre>

<div class="note">
  <code>_required_tools.json</code>, generated from the CLI commands the Mold actually cites — install line, ephemeral
  fallback, and a check the agent can run before it starts.
</div>

</section>

{/* SLIDE 9 — the rule underneath all of it */}

<section class="galaxy-cover divider vstack" data-background-gradient="linear-gradient(135deg, #2c3143 0%, #25537b 100%)">

<div class="statement">Never fabricate around a gap.</div>

<div class="lede" style="font-style: italic;">An open obligation is the honest state.</div>

<div class="note">
  Inventing a tool id, a connection, or a value so the artifact looks complete converts a tracked gap into a silent
  defect — the exact failure the whole apparatus exists to end.
</div>

</section>

{/* SLIDE 10 — the ledger, and surrender as a named outcome */}

<section class="vstack">

<h2>So an unresolved dep becomes a tracked entry</h2>

<div class="body measure">
  Every reading above ends in the same artifact: the <strong>open-requirements ledger</strong>, threaded through the run.
  A Mold that hits a gap <strong>appends</strong>; a later Mold whose decision closes it <strong>marks it resolved</strong>.
  When nothing downstream can close one, the escalation cap is reached, the entry is marked <code>surrendered</code>, and
  it ships in the draft as a <strong>labelled gap</strong> — the run does not spin, and does not invent.
</div>

<div class="cards cards-3 measure-lg">
  <div class="card">
    <div class="card-title">visible</div>
    <div class="card-body">never silently dropped</div>
  </div>
  <div class="card card-gold">
    <div class="card-title">attributed</div>
    <div class="card-body"><code>raised_by</code> / <code>resolved_by</code> are the audit trail</div>
  </div>
  <div class="card card-grey">
    <div class="card-title">actionable</div>
    <div class="card-body">a reviewer knows exactly where to look</div>
  </div>
</div>

<div class="note">The ledger is not a questions-for-a-human list. It is materialized in the artifact, so it behaves the same in anyone's harness.</div>

</section>

<section class="vstack">

<div class="eyebrow">The outside loop · guinea pigs wanted</div>

<h2>Two commands, and a lot of threads to pull on</h2>

<div class="cards measure-lg" style="gap: 12px;">
  <div class="card card-side card-note">
    <div class="card-eyebrow">1 · pick a workflow, then ask for a scenario</div>
    <em>"Investigate how scenarios.md works generally and for the nextflow-to-galaxy pipeline, and set up a
    scenarios.md entry and fixture for Nextflow workflow X."</em>
  </div>
  <div class="card card-side card-gold card-note">
    <div class="card-eyebrow">2 · compact the session</div>
    Clear the investigation out of context before the run that matters.
  </div>
  <div class="card card-side card-gold card-note">
    <div class="card-eyebrow">3 · run it</div>
    <code>/test-pipeline nextflow-to-galaxy X</code>
  </div>
</div>

<div class="callout measure">
  Those two queries trigger a whole lot of work and self-evaluation. Your agent builds and tests a workflow, and hands
  you the threads.
</div>

<div class="note">
  nf-core and non-nf-core are both supported — this is how <code>egapx</code> got tested. Doing the same against
  production artifacts is next, per Dannon's suggestion.
</div>

</section>

{/* SLIDE 13 — the inside loop: the run reports on the Foundry */}

<section class="vstack">

<div class="eyebrow">The inside loop · PR #474, open</div>

<h2>The run files feedback on the Foundry while it runs</h2>

<div class="body measure">
  An opt-in second ledger. Not unmet requirements of the workflow being built — those stay in the open-requirements
  ledger — but <strong>gaps, defects, friction, and wishes about the Foundry's own Molds and references</strong>.
</div>

<div class="cards cards-3 measure-lg">
  <div class="card">
    <div class="card-title">what gets recalled</div>
    <div class="card-body">where the skill guessed at something the instructions should have settled, needed what its bundle doesn't carry, or hit contradicting instructions</div>
  </div>
  <div class="card card-gold">
    <div class="card-title">not asked</div>
    <div class="card-body">"was anything unclear?" — a question that reliably answers itself <em>no</em></div>
  </div>
  <div class="card card-grey">
    <div class="card-title">then triaged</div>
    <div class="card-body">a 48th Mold clusters by locator, checks current main, searches duplicates, redacts, and drafts</div>
  </div>
</div>

<div class="callout callout-sm measure">
  A skill that says nothing has not reported a clean pass. <code>no feedback</code> has to be said out loud — that is what
  separates a phase that looked for friction from one that never looked.
</div>

<div class="note">Upstream faults get filed here too, with the run analysis attached, and a maintainer forwards. Every GitHub mutation waits for explicit confirmation.</div>

<a class="ref-link" href="https://github.com/galaxyproject/foundry/pull/474">galaxyproject/foundry#474 — runtime feedback ledger ↗</a>

</section>

{/* SLIDE 14 — the route, start to finish */}

<section class="vstack">

<h2>You noticed a gap. The route.</h2>

<div class="cards measure-lg" style="gap: 11px;">
  <div class="card card-side card-note">
    <div class="card-eyebrow">1 · locate</div>
    Whose knowledge is this? If upstream owns it, the Foundry cites — it does not re-explain.
  </div>
  <div class="card card-side card-gold card-note">
    <div class="card-eyebrow">2 · type it</div>
    Pick the kind: pattern, research note, CLI page, schema note, or a new Mold.
  </div>
  <div class="card card-side card-gold card-note">
    <div class="card-eyebrow">3 · write</div>
    Hand edit, or drive one of the authoring slash commands — <code>/review-mold</code>, <code>/refine-mold</code>, <code>/cast</code>.
  </div>
  <div class="card card-side card-grey card-note">
    <div class="card-eyebrow">4 · validate</div>
    <code>npm run validate</code> — schema plus cross-file resolution. Errors block.
  </div>
  <div class="card card-side card-grey card-note">
    <div class="card-eyebrow">5 · cast &amp; check</div>
    Re-cast anything downstream; the drift gates decide whether you got it right.
  </div>
</div>

<div class="note">Then a normal PR. CI re-casts touched Molds and puts the generated diff in front of the reviewer.</div>

</section>

<h2>What counts as canon</h2>

<div class="statement statement-sm">Source authority beats local copies.</div>

<div class="cards cards-4 measure-lg">
  <div class="card">
    <div class="card-title">IWC</div>
    <div class="card-body">workflows belong in IWC</div>
  </div>
  <div class="card card-gold">

  </div>
  <div class="card card-gold">

  </div>

  upstream as the canonical home of it.
</div>

</section>

{/* SLIDE 16 — so what does "using" upstream look like */}

<section class="vstack vstack-tight">

<h2>So upstream material is pinned, licensed, and framed</h2>

<pre style="font-size: 0.42em; line-height: 1.55; text-align: left; margin-left: auto; margin-right: auto; max-width: 38em; padding: 0.9em 1.1em; border: 0;"><code style="display: block; padding: 0;">{`- local: content/research/galaxy-xsd/galaxy.xsd

<div class="note">

{/* SLIDE 20 — the four-part argument */}

<section class="vstack">

<h2>Why exploring beats specifying</h2>

<div class="cards cards-2 measure-lg">
  <div class="card">
    <div class="card-title">You test piece by piece</div>
    <div class="card-body">Each step runs on the real data before the next one is chosen. A result is ground truth; a validated draft step is a well-formed guess.</div>
  </div>
  <div class="card card-gold">
    <div class="card-title">You and the agent explore together</div>
    <div class="card-body">The agent sees the same outputs you do. It can propose a hypothesis, run it, and read what came back.</div>
  </div>
  <div class="card card-gold">
    <div class="card-title">Hypotheses get tested, not declared</div>
    <div class="card-body">"Does this filter leave enough peaks?" is answered by a number, not by a schema check.</div>
  </div>
  <div class="card card-grey">
    <div class="card-title">You can be redirected</div>
    <div class="card-body">The analysis is allowed to change shape as you both learn. A pipeline's spine is fixed at phase one.</div>
  </div>
</div>

</section>

{/* SLIDE 21 — the sharpest contrast, stated against my own approach */}

<section class="vstack">

<h2 class="plain-heading measure" style="font-size: 1.26em; line-height: 1.16;">
  The Foundry's pipelines construct from <em>intent</em>. Nothing runs until the end.
</h2>

<div class="split split-vs measure-lg">
  <div class="panel">
    <div class="card-eyebrow">construct</div>
    <div class="card-title card-title-lg">needs only the intent</div>
    <div class="card-body">every step is schema-valid, version-pinned, and unexecuted until the test tail</div>
  </div>
  <div class="split-mark">vs</div>
  <div class="panel">
    <div class="card-eyebrow">explore</div>
    <div class="card-title card-title-lg">needs only the data</div>
    <div class="card-body">every step is executed, and the next decision is made against what actually came out</div>
  </div>
</div>

<div class="callout callout-warn measure" style="margin-top: 16px;">
  A validated workflow that nobody has run is a strong hypothesis about an analysis. It is not the analysis.
</div>

</section>

<div class="eyebrow">Part Four</div>

<div class="statement">"How does casting actually work? What does a Mold look like?"</div>

</section>

{/* SLIDE 29 — a real Mold, frontmatter first */}

<section class="vstack vstack-tight">

<h2>A Mold is frontmatter plus a procedure</h2>

<pre style="font-size: 0.4em; line-height: 1.5; text-align: left; margin-left: auto; margin-right: auto; max-width: 38em; padding: 0.9em 1.1em; border: 0;"><code style="display: block; padding: 0;">{`type: mold
name: discover-shed-tool
axis: target-specific
target: galaxy
status: reviewed
revision: 5
summary: "Search the Tool Shed for an existing wrapper, drill from hit
          to a pinnable changeset, classify candidates, and recommend
          or fall through."

output_artifacts:
  - id: galaxy-tool-pin
    kind: json
    default_filename: galaxy-tool-pin.json
    schema: "[[galaxy-tool-discovery]]"

references:
  - kind: cli-command
    ref: "[[tool-search]]"
    ...`}</code></pre>

<div class="note">Everything a caller needs to route to this Mold, and everything casting needs to package it. Then the body.</div>

</section>

{/* SLIDE 30 — and the body is just prose */}

<section class="vstack vstack-tight">

<div class="eyebrow">the same Mold, below the frontmatter</div>

<h2>The procedure is prose</h2>

<div class="panel measure left">

<div style="font-family: var(--r-code-font); font-size: 0.46em; color: var(--deck-grey); letter-spacing: 0.02em;"># discover-shed-tool</div>

<div class="body" style="max-width: none; margin-top: 12px;">
  Discover whether the Galaxy Tool Shed already publishes a wrapper for the tool a workflow step needs, and resolve the
  discovery to an <code>(owner, repo, tool_id, version, changeset_revision)</code> quintuple that downstream steps can
  pin and cache.
</div>

<div class="body" style="max-width: none; margin-top: 14px;">
  This Mold is the <strong>Tool Shed leg</strong> of the <code>discover-or-author</code> branch in Galaxy-targeting
  per-step pipelines. On a hit, the cast skill recommends a pin and exits successfully. On a miss (or a low-quality
  hit), it falls through to <code>[[author-galaxy-tool-wrapper]]</code>. The branch itself is harness logic; this Mold
  owns only the discovery half.
</div>

</div>

<div class="note">
  No prompt engineering, no XML scaffolding, no tone. Prose a maintainer can read and argue with — then
  <code>## Inputs</code>, <code>## Outputs</code>, <code>## Procedure</code>, and the wiki-links resolve at cast time.
</div>

</section>

{/* SLIDE 31 — the typed reference */}

<section class="vstack vstack-tight">

<h2>Every reference carries its own decisions</h2>

<pre style="font-size: 0.4em; line-height: 1.5; text-align: left; margin-left: auto; margin-right: auto; max-width: 38em; padding: 0.9em 1.1em; border: 0;"><code style="display: block; padding: 0;">{`references:
  - kind: research
    ref: "[[galaxy-collection-semantics]]"
    used_at: runtime
    load: on-demand
    mode: verbatim
    evidence: corpus-observed
    purpose: "Choose Galaxy collection input shapes (File / list / paired /
              list:paired / record) from the source's per-sample, paired,
              grouped, or nested data descriptions."
    trigger: "When the summary describes paired reads, per-sample groups,
              nested or grouped inputs, or any input that should become a
              Galaxy dataset collection."`}</code></pre>

<div class="note"><code>trigger</code> is <em>required</em> when load is <code>on-demand</code>; <code>verification</code> is required when evidence is still <code>hypothesis</code>. The schema refuses the shortcut.</div>

</section>

{/* SLIDE 32 — the three casting decisions */}

<section class="vstack">

<h2>Three decisions decide how a reference is packaged</h2>

<div class="cards cards-3 measure-lg">
  <div class="card">
    <div class="card-title">used_at</div>
    <div class="card-body">cast time, runtime, or both — whether the agent ever sees it at all</div>
  </div>
  <div class="card card-gold">
    <div class="card-title">load</div>
    <div class="card-body">upfront, or on-demand behind a declared <code>trigger</code></div>
  </div>
  <div class="card card-grey">
    <div class="card-title">mode</div>
    <div class="card-body">verbatim into the body, or a sidecar file the agent opens when it needs it</div>
  </div>
</div>

<div class="callout measure">
  This is progressive disclosure as a <strong>compile-time contract</strong>. <code>discover-shed-tool</code> gets its
  output schema upfront and its four notes on demand — so the Tool Shed indexing gotchas cost nothing until search
  results actually look wrong.
</div>

<div class="note">And <code>evidence</code> rides on the same entry — so one line says what a reference is, when it loads, how it lands, and how much we trust it.</div>

</section>

{/* SLIDE 33 — casting is per-kind dispatch */}

<section class="vstack vstack-tight">

<h2>Casting is per-kind dispatch</h2>

<div class="cards cards-3 measure-lg" style="gap: 12px;">
  <div class="card">
    <div class="card-title">pattern · research</div>
    <div class="card-body">verbatim copy into <code>references/</code></div>
  </div>
  <div class="card card-gold">
    <div class="card-title">cli-command</div>
    <div class="card-body">deterministic JSON sidecar from registry metadata</div>
  </div>
  <div class="card card-grey">
    <div class="card-title">schema</div>
    <div class="card-body">the named package export, imported at build time and serialized</div>
  </div>
</div>

<div class="body measure" style="margin-top: 16px;">
  Which path a kind takes is not knowledge the caster holds. Each kind declares its own <code>cast:</code> block —
  resolve strategy, default mode, slug field — in <code>reference_contract.yml</code>.
</div>

<div class="note">A kind with no <code>cast:</code> block is not castable. That is how <code>example</code> is refused today, without a second list inside the caster to keep in step.</div>

</section>

{/* SLIDE 34 — what lands in the bundle */}

<section class="vstack vstack-tight">

<h2>What actually lands in the bundle</h2>

<pre style="font-size: 0.44em; line-height: 1.6; text-align: left; margin-left: auto; margin-right: auto; max-width: 32em; padding: 0.9em 1.1em; border: 0;"><code style="display: block; padding: 0;">{`casts/claude/skills/discover-shed-tool/
  SKILL.md                 rendered from the Mold, never hand-edited
  _provenance.json         what was cast, from where, at which hash
  _required_tools.json     the CLI it needs, and how to check for it
  _verify.json             how to validate what it emits
  references/
    schemas/               loaded upfront
    cli/                   sidecars, loaded on demand
    notes/                 loaded on demand`}</code></pre>

<div class="note">Isolated: no links back to the Foundry, no runtime dependency on it. Casting <em>is</em> the integration boundary.</div>

</section>

{/* SLIDE 39 — how it relates to the Foundry */}

<section class="vstack">

<h2>How it reaches the Foundry</h2>

<div class="body measure">
  The TDA Bioinformatics Foundry — the third instance — consumes Biopixi as a <strong>typed note kind</strong>. An
  Environment is a note, and its portability grade is a field on that note.
</div>

<div class="statement statement-sm">Installing is a measurement.</div>

<div class="body measure">
  A writeup of a tool is not knowledge about the tool until something can run it. Building those environments surfaced
  unsolvable dependency closures, absent channels, a build needing <code>cmake &lt;4</code>, and a package name already
  taken by something unrelated — none of which reading would have found.
</div>

<div class="callout callout-sm measure">
  The grade is about the environment. It is <strong>not</strong> the Foundry's scientific acceptance check — those stay
  separate on purpose.
</div>

</section>

{/* SLIDE 40 — how it relates to Galaxy */}

<section class="vstack">

<h2>How it reaches Galaxy</h2>

<div class="flow">
  <div class="flow-node">pixi environment</div>
  <span class="flow-arrow">→</span>
  <div class="flow-node">conda recipe</div>
  <span class="flow-arrow">→</span>
  <div class="flow-node">published container</div>
  <span class="flow-arrow">→</span>
  <div class="flow-node flow-node-muted">Galaxy tool requirements</div>
</div>

<div class="body measure" style="margin-top: 20px;">
  The ladder's top rung is a community-published, observed BioContainer — which is the road a Galaxy tool's dependencies
  already travel. Biopixi grades how far along that road a method has actually gotten, and a conda recipe is written
  where the public channels carry nothing recent enough.
</div>

<div class="note">
  So: not a Galaxy component, and not part of the Foundry Pattern. A shared rung that a Foundry can type and Galaxy can
  consume.
</div>
